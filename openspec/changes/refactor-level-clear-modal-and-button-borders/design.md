## Context

`docs/menu.js` 中的通關彈窗目前繪製 `340px` 高的背景框（`roundRect(200, 100, 400, 340, 20)`），標題、副標題與按鈕的垂直排版間距過大。`createMenuButton` 使用單色無邊框的背景填色（`0x34495e`），使按鈕容易與深色海底背景混在一起。

相關動機請參閱 `proposal.md`。

## Goals / Non-Goals

**Goals:**
- 精簡彈窗尺寸：背景框高度從 `340px` 縮減為 `220px`（`roundRect(200, 115, 400, 220, 20)`）。
- 統一按鈕寬度：「下一關」與「返回關卡選擇」按鈕寬度均設為 `width = 220`。
- 規範各模式佈局：
  - **一般關卡（2 按鈕）**：「下一關」（`y = 225`）、「返回關卡選擇」（`y = 280`）。主標題 `y = 160`，`clearSubText.text = ""`。
  - **挑戰模式（1 按鈕）**：「返回關卡選擇」（`y = 250`）。主標題 `y = 160`，`clearSubText.text = ""`。
  - **計時模式（1 按鈕）**：「返回關卡選擇」（`y = 265`）。主標題 `y = 150`，單行 `clearSubText.text = "本次成績: ..."` 位於 `y = 195`。
- 選單按鈕外框樣式：更新 `createMenuButton()` 繪製邏輯，使用 `.fill(0x34495e).stroke({ width: 3, color: 0xff7675 })` 以及 Hover 外框 `0xf9ca24`。

**Non-Goals:**
- 不修改關卡通關邏輯、計時器計算或最高紀錄存檔機制。
- 不調整遊戲內的物理效果或障礙物機制。

## Decisions

### 1. 統一 `createMenuButton` 的 stroke API 使用
- **選擇**：使用 Pixi.js v8 `.stroke({ width: 3, color: 0xff7675 })`，並在 `pointerover`/`pointerout` 事件中更新邊框顏色。
- **理由**：讓主選單、關卡選擇、挑戰模式與彈窗對話框中的按鈕渲染保持 DRY。
- **替代方案**：僅針對彈窗按鈕加入邊框。放棄原因為全域粉紅外框更能提升整體 UI 對比度。

### 2. 計時模式單行格式化成績
- **選擇**：將成績合併為單行字串 `本次成績: ${timeStr}`，若破紀錄則在同行末端加上 `(🎉 刷新紀錄!)`（位於 `y = 195`）。
- **理由**：避免多行折行，完美適應精簡版 220px 彈窗。

## Risks / Trade-offs

- **[風險]** 若 Canvas 視窗縮放，彈窗按鈕位置可能與背景框錯位。
  - **緩解措施**：所有座標均相對於 `menu.js` 中 Pixi 容器縮放所使用的固定 800x600 座標系。
